# Testing

Test requirements for znvme implementation work.

## Required commands

- `zig build test` runs the host suite.
- `zig build check` type-checks the `nvme` module for `x86_64-freestanding`, proving wire-layout ABI assertions off-host.
- The default test command requires no external tools.

## Test locations

- In-source `test` blocks cover local pure logic in the file they test.
- `test/` contains multi-module tests, golden byte comparisons, fixture-driven tests, and integration-style tests, mirroring `src/`. The aggregator `test/all.zig` wires them for `zig build test`.

## Test naming

Use category prefixes:

```zig
test "unit: registers decode CAP doorbell stride" { ... }
test "golden: identify namespace minimal bytes" { ... }
test "malformed: identify buffer shorter than structure" { ... }
test "roundtrip: read command encodes and decodes through SQE view" { ... }
```

## Host-test model

Every module under `core/`, `controller/`, `commands/`, `identify/` builds and tests on the host. There is no `freestanding`-only code in the test path.

- **Registers** are exercised through the typed accessor backed by a plain `[]u8`. That is a real backing buffer, not a mock; on-target the same accessor aliases MMIO.
- **DMA** is a caller-owned slice paired with a fabricated `stdx.addr.DmaAddr` (`stdx.dma.Buffer(T).init(&heap_slice, DmaAddr.fromInt(...))`); on-target zfw passes an identity-mapped page or an IOMMU IOVA.
- **Time** is an injected monotonic source the test drives deterministically; no test busy-waits on a real clock.

## No mocks

- Tests use real byte buffers for registers, queues, commands, and Identify structures.
- Tests do not mock the register accessor, the queue ring, command builders, or completion decoders.
- znvme owns no UEFI protocol invocation; nothing UEFI-side is mocked here. On-VM integration against a real controller is zfw's gate.

## Unit coverage

Each public type has tests for:

- successful construction / validation for the smallest valid value;
- successful construction / validation for a non-trivial value;
- every public error variant;
- boundary lengths for every variable-length field;
- round trip where a builder exists (encode → decode through the matching view).

## Required per-module test set

Each implemented module includes:

- one success test for the smallest valid value;
- one success test for a non-trivial value;
- one malformed-input test per public error variant;
- one boundary-length test for every variable-length field;
- one round-trip test for every command/entry builder.

## Round trips

Every command builder round-trips through its matching wire view:

```text
Builder -> encode into caller SQ slot -> SQE.View.from -> field accessors match inputs
```

Completion decode round-trips against a constructed CQE:

```text
construct CQE bytes -> CQE.View.from -> status / command-id / sq-head accessors
```

## NVMe-specific required coverage

Beyond the per-module set, the suite must cover:

- **Controller init** — CC/CSTS enable→ready transitions, disable→reset, and the enable timeout path against the injected time source.
- **Queue ring** — SQ-full and CQ-empty edges; head/tail wrap; the phase-tag flip across a full CQ wrap; doorbell value and stride math.
- **PRP** — single-page transfer, page-spanning transfer, and the threshold where a PRP list is required.
- **Identify** — Identify Namespace LBA-format selection, including rejection of a reserved or out-of-range format index; geometry derivation (LBA size, capacity).
- **Status** — CQE status decode for success and a representative error (a Status Code Type / Status Code pair).

## Fixtures

- Golden fixtures are checked into the repository.
- Golden fixtures are real NVMe structure bytes or generated by znvme builders.
- Generated fixtures carry a documented regeneration command and live under a test fixture directory.
- Fixture updates include the source input and the generated bytes when both exist.
- Default `zig build test` must not require external tools.

## Golden tests

Golden tests compare bytes exactly. A golden diff is an API change: a byte change is accepted only when the corresponding spec or builder input changed.
