# Verification test strategy

Status: Approved.

This spec owns znvme's host-test contract. It fixes what "host-test" means for znvme, what substrates each domain runs against, what tests every module authors, how golden fixtures are managed, and what the default `zig build test` command excludes. Every per-type spec's `## Required tests` section satisfies this spec; conflicts are defects.

This spec does not restate the build wiring or the test-tree layout — `docs/specs/architecture.md` owns those. It also does not restate style overlays — `docs/guidelines/testing.md` extends this spec, and `docs/guidelines/conventions.md` extends `docs/specs/architecture.md`. On conflict, spec order per `docs/guidelines/conventions.md` §"Authority order" wins.

## Owned scope

This spec owns:

- the host-test contract: real byte buffers, real caller-owned DMA slices, injected clock backends, real `stdx.barrier.*` lowering on the host test target;
- the no-mocks rule: the register accessor, queue rings, command builders, and completion decoders are exercised as landed; test code never introduces a stand-in for a znvme type;
- the test naming vocabulary — `unit:`, `golden:`, `malformed:`, `roundtrip:` prefixes — and its per-prefix meaning;
- the per-module required-test set: smallest valid value, non-trivial value, one malformed-input test per public error variant, one boundary-length test per variable-length field, one round-trip test per builder / view pair, one golden test per wire-format byte contract;
- the NVMe-specific coverage floor: controller-init CC/CSTS transitions and enable-timeout, queue-ring SQ-full / CQ-empty edges and phase-tag wrap, PRP single-page / spanning / list-required threshold, Identify Namespace LBA-format selection and geometry derivation, and CQE status decode for success plus one representative failure;
- the fixture policy: real NVMe bytes or bytes generated by a znvme builder; regeneration command lives alongside the fixture; a byte diff is an API change; default `zig build test` requires no external tools;
- the fixture-tree convention: `test/fixtures/<domain>/<name>.bin` with a colocated `test/fixtures/<domain>/<name>_regen.zig` (or a documented command noted next to the fixture) that reproduces the bytes end-to-end;
- the rule that in-source `test` blocks cover local pure logic and multi-module / golden / malformed / round-trip tests live under `test/`;
- the approved `std` / `stdx` surface inside tests, extending the architecture spec's §"`std` and `stdx` usage" list;
- the manifest — a canonical list of every `test/**/*_test.zig` file each approved per-type spec requires, so coverage is auditable in one document.

## Deferred scope and non-goals

This spec does not own:

- repository layout, aggregator wiring, and build-step definitions — `docs/specs/architecture.md`;
- the validation-phase vocabulary (compile-time, public validation, assertions) — `docs/specs/architecture.md` §"Validation phases";
- Zig style rules (imports, comments, naming, formatting) — `docs/guidelines/zig.md` and `docs/guidelines/conventions.md`;
- per-type behaviors under test — each per-type spec's `Required tests` list;
- on-VM integration against a real controller — zfw's gate, not znvme's;
- fuzzing, property-based generators, and simulation harnesses — a future spec claims them;
- coverage instrumentation or coverage-target thresholds — the required-test set is the coverage floor;
- UEFI protocol test doubles — znvme owns no UEFI surface;
- big-endian host or target compatibility.

## `stdx` composition

Test code composes only the caller-facing `stdx` primitives znvme itself consumes:

- `stdx.dma.Buffer(T).init(&heap_slice, stdx.addr.DmaAddr.fromInt(...))` — real caller-owned host storage paired with a fabricated DMA address; tests treat the DMA address as opaque;
- `stdx.io.Mmio.Window` — backed by a real `[N]u8 align(@alignOf(u64))` (or `align(Mmio.Window.min_align)`) scratch buffer, exercised through the same typed accessors that alias MMIO on target;
- `stdx.time.Clock.Monotonic(Backend)` with a test-supplied counter backend whose `now()` advances deterministically per call;
- `stdx.time.Deadline`, `stdx.time.Duration`, `stdx.time.Backoff` — composed exactly the way `docs/specs/controller/init.md` and `docs/specs/controller/queue.md` compose them at runtime;
- `stdx.barrier.mmio.*` and `stdx.barrier.dma.*` — execute their real x86_64 lowering on the host test target; tests assert API shape and referential mapping through the `stdx` spec, not hardware ordering;
- `stdx.tags.TagAllocator.Bounded(CidDomain, u16)` — instantiated over a caller-owned `[]u64` word slice, same as the production surface.

## Host-test substrates

Each domain has one substrate shape. Tests never introduce a second shape for the same domain.

### Register substrate

Register-touching tests allocate a `[N]u8 align(@alignOf(u64))` scratch buffer, pass it to `ControllerRegisters.at`, and drive reads and writes through the typed accessor. Register values (`Cap`, `Csts`, ...) round-trip through `fromRaw` / `raw`. On target, the same accessor aliases MMIO.

### DMA substrate

DMA-touching tests wrap caller-owned host storage in `stdx.dma.Buffer(T).init(&heap_slice, stdx.addr.DmaAddr.fromInt(fake_iova))`. The fake IOVA is opaque; znvme never dereferences it. On target, zfw supplies an identity-mapped page or an IOMMU-installed IOVA.

### Time substrate

Waiting paths accept a `stdx.time.Clock.Monotonic(Backend)`. Tests supply a `Backend` whose `now()` increments deterministically per call. Tests never busy-wait on wall time.

### Barrier substrate

`stdx.barrier.mmio.*` and `stdx.barrier.dma.*` execute their real x86_64 lowering on the host test target. Tests assert API shape and referential mapping through the `stdx` spec, not hardware ordering.

### Queue substrate

Queue-touching tests compose a `SubmissionQueue`, `CompletionQueue(Backend)`, or `Pair(Backend)` from caller-owned DMA storage, a caller-owned MMIO byte buffer for the doorbell, and a caller-owned `[]u64` CID bitmap. Tests inspect the caller-owned MMIO byte buffer to verify doorbell writes and read `Sqe` / `Cqe` values through the same accessors production code uses.

## No mocks

Tests exercise landed code. The following are prohibited:

- a stand-in for `ControllerRegisters`, `SubmissionQueue`, `CompletionQueue(Backend)`, `Pair(Backend)`, any `Sqe` / `Cqe` accessor, any command builder, or any Identify view;
- a wrapper that intercepts `stdx.io.Mmio.Register` loads or stores;
- a wrapper that intercepts `stdx.barrier.*` calls;
- a wall-clock time source in place of the injected monotonic backend.

znvme owns no UEFI protocol invocation and no PCI enumeration. Nothing UEFI-side or PCI-side is mocked here. On-VM integration against a real controller is zfw's gate.

## Test naming vocabulary

Every test in `test/**/*_test.zig` carries exactly one of these prefixes. The prefix carries meaning:

- `unit:` — exercises one method or one small composition against constructed inputs. No fixture bytes; no round-trip through a paired encoder/decoder.
- `golden:` — asserts exact bytes against a checked-in fixture. Fixture bytes are real NVMe structure bytes or bytes generated by a znvme builder; a byte diff is an API change.
- `malformed:` — a public validation entry point (`T.validate(bytes)`, `Aqa.fromDepths`, `QueueBase.fromDmaAddr`, ...) rejects a specific invalid input with a specific typed error. One test per public error variant.
- `roundtrip:` — a builder or in-place `init` writes bytes through one API, and matching accessors decode them back through the paired API. Encoded value equals decoded value on every accessor.

A test that does not fit these prefixes is a defect. Combine multiple behaviors into one test only when the assertions share a single input construction and the description names each behavior explicitly.

## Per-module required-test set

Every module implementing a public type authors, at minimum:

- one `unit:` success test for the smallest valid input;
- one `unit:` success test for a non-trivial input covering every accessor;
- one `malformed:` test per public error variant;
- one `unit:` boundary-length test per variable-length field;
- one `roundtrip:` test per builder / view pair or `init` / accessor pair;
- one `golden:` test per wire-format byte contract the module owns.

A module without a paired builder or view omits the `roundtrip:` line. A module without wire-format byte contracts (pure semantic types such as `Geometry` and `CompletionStatus`) omits the `golden:` line.

## NVMe-specific coverage floor

Beyond the per-module set, the suite covers, at minimum:

- **Controller init** — CC/CSTS enable → ready transitions, disable → reset, and the enable-timeout path against the injected time source (`docs/specs/controller/init.md`);
- **Queue ring** — SQ-full and CQ-empty edges; head/tail wrap; the phase-tag flip across a full CQ wrap; doorbell value and stride math (`docs/specs/controller/queue.md`, `docs/specs/core/doorbell.md`);
- **PRP** — single-page transfer, page-spanning transfer, and the threshold where a PRP list is required (`docs/specs/core/prp.md`);
- **Identify** — Identify Namespace LBA-format selection including rejection of a reserved or out-of-range format index, and geometry derivation for LBA size and capacity (`docs/specs/identify/namespace.md`);
- **Status** — CQE status decode for success and a representative error, exercising both `CompletionStatus.from` and one `failure()` variant (`docs/specs/core/status.md`).

## Fixture policy

Every golden fixture:

- is checked into the repository under `test/fixtures/<domain>/<name>.bin`;
- carries either a colocated `test/fixtures/<domain>/<name>_regen.zig` regeneration program (invoked via `zig run`) or, when the fixture is real NVMe-controller-authored bytes captured verbatim, a documented capture command written next to the fixture;
- contains real NVMe structure bytes or bytes generated by a znvme builder — never handcrafted numbers;
- updates land alongside the source input and the generated bytes when both exist.

Default `zig build test` requires no external tools; regeneration commands run through `zig run` against modules already in the build.

A golden diff is an API change: a byte change is accepted only when the corresponding spec, builder input, or captured NVMe bytes changed. The corresponding per-type spec updates in the same commit.

## `std` and `stdx` inside tests

Extends `docs/specs/architecture.md` §"`std` and `stdx` usage" for test code:

Approved:

- `std.testing` and its helpers (`expectEqual`, `expectError`, `expect`, ...);
- `std.mem` compile-time helpers permitted by the architecture spec, plus `std.mem.eql` on comptime-known slices;
- heap-allocated scratch buffers used only to back `stdx.dma.Buffer(T)`, `stdx.io.Mmio.Window`, CID bitmaps, and fixture bytes;
- fixture-regeneration helpers under `test/fixtures/**` that compose znvme's public builders;
- local test-only backend types (counter clocks, scripted CSTS providers) declared in the same `_test.zig` file that consumes them.

Prohibited:

- any `std.time.*` source of wall time;
- any `std.os.*` or `std.fs.*` I/O outside `zig build`-provided fixture reads;
- any stand-in for the znvme types listed in §"No mocks";
- reimplementations of `stdx` primitives — an unmet test-time need is proposed upstream against `../zstdx`, not shadowed here.

## Example usage

Illustrative shape only; not part of the approved API. Every module's `Required tests` section owns the specific behaviors under test; the examples below show the substrate shape a passing test composes.

Register substrate exercising the `storeCap` / `cap` symmetric accessor pair:

```zig
const std = @import("std");

const nvme = @import("nvme");

const Cap = nvme.core.registers.Cap;
const ControllerRegisters = nvme.core.registers.ControllerRegisters;

test "unit: controller registers storeCap writes CAP through the mmio window and cap reads it back" {
    var bar_bytes: [0x1000]u8 align(@alignOf(u64)) = @splat(0);
    const regs = try ControllerRegisters.at(&bar_bytes);

    regs.storeCap(Cap.fromRaw(0x1400_0000)); // TO = 20, other fields zero

    try std.testing.expectEqual(@as(u8, 20), regs.cap().readyTimeoutUnits500ms());
}
```

Counter backend composed into `stdx.time.Clock.Monotonic(CounterBackend)`; `docs/specs/controller/init.md` §"Example usage" shows the full construction against a real `Controller`:

```zig
const stdx = @import("stdx");

const CounterBackend = struct {
    ticks_ns: u64 = 0,

    pub fn now(self: *CounterBackend) stdx.time.Instant {
        self.ticks_ns += 1_000_000; // 1 ms per call
        return @enumFromInt(self.ticks_ns);
    }
};
```
